# explain-plainly

## How to explain
- **Big picture first.** Three to five bullets: what it is, what it does, why it
  matters. Details only after.
- **Plain words.** Define every term the first time, in one short sentence. No
  unexplained acronyms or citation jargon.
- **Numbers mean something.** Say what a figure measures, its range, and whether
  it is good ("0.77 is the similarity score: 1 is identical, so this is a close
  match").
- **Short.** If the user says it's too much, cut it in half and keep only what
  they need to act.
- Ground everything in the actual repo and results. Don't guess.

## Meeting or viva prep
Answer in the user's own frame. A good default:
1. What I have now.
2. What I'll show next.
3. What the full product will be.
4. My contribution (what's new).
Add the likely questions with one-line answers.

## Learning a codebase fast
Give an ordered path: run it, then read the entry point, then the core module,
then one test. Pair each code step with the doc section or source that explains
the theory. Keep it to what can be done in the time the user has.
